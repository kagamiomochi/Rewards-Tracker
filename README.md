# Rewards Tracker

Microsoft Rewards の「使用可能なポイント」を毎日自動で記録して、推移を折れ線グラフで見るための Android アプリです。

ポイントの獲得を自動化するものではありません。毎日のポイント数を記録するためだけのアプリです。

## 機能

- 指定した時刻にバックグラウンドでポイント数を取得して、取得のたびに端末内に保存する (1日に何回でも設定できる。初期値は 00:00 と 12:00)
- 取得時刻は「取得時刻」ボタンから追加、削除できる (0:00 は 24時にあたる)
- 直近30日の折れ線グラフと、取得ごとのポイント数と前回比の一覧を表示する
- 「今すぐ取得」ボタンで手動取得できる。直前の取得結果のログがホーム画面に出る
- セッション切れや取得失敗のときは通知で知らせる

## 技術構成

- Kotlin + Jetpack Compose (minSdk 26 以上)
- WorkManager (定期実行)
- WebView (ログインと、ポイントの読み取り)
- SharedPreferences に JSON で保存 (ポイントの記録と、取得時刻の設定)

Room は使っていません。AGP 9 の内蔵 Kotlin 構成では KSP の設定が合いにくく、保存するのは1日1件程度なので、軽い保存方式に置き換えました。OkHttp も使っていません。

### 依存関係

`app/build.gradle.kts` の `dependencies` に次を追加します。

```kotlin
implementation("androidx.work:work-runtime-ktx:2.10.1")
implementation("androidx.lifecycle:lifecycle-runtime-compose:2.9.0")
```

バージョンは例です。新しい安定版があれば上げて構いません。`minSdk` は 26 以上にします (`java.time` を使うため)。

### パーミッション

`AndroidManifest.xml` に次の2つを追加します。

```xml
<uses-permission android:name="android.permission.INTERNET" />
<uses-permission android:name="android.permission.POST_NOTIFICATIONS" />
```

## 使い方

1. アプリを起動して、通知の許可を求められたら許可する。
2. ホームの「ログイン」を押して、表示された WebView で Microsoft アカウントにサインインする。
3. ダッシュボードが表示されたら、画面下の「ダッシュボードが表示されたら押す」を押す。
4. 押した直後に1回取得される。以降は設定した時刻に自動で取得される。
5. 取得する時刻を変えたいときは、ホームの「取得時刻」を押して、時刻を追加または削除する。変更はすぐに予約へ反映される。時刻は1つ以上必要。

ログインは、必ずアプリ内の WebView で行います。スマホの Chrome など別のブラウザでログインしても、Cookie が共有されないのでアプリには引き継がれません。

## 取得の仕組み

1. 非表示の WebView で `https://rewards.bing.com/` を開く。ログインで保存された Cookie がそのまま使われる。
2. ダッシュボードはクライアント側で描画されるので、1秒ごとに最大25回、画面の文字を調べる。
3. 「使用可能なポイント」(または "Available points") というラベルの次の行にある数字を、ポイント数として読み取る。見つからない場合は、`AvailablePoints` という名前の属性を持つ要素から読む予備の方法を試す。
4. 読み取れたら、取得時刻つきの記録として保存する。1日に何回取得しても、すべて別の記録として残る。

### 取得の予約の仕組み

WorkManager の定期実行 (PeriodicWork) は、決まった時刻に動かせません。そこで、次回分の1回限りのジョブを1件だけ登録して、実行されたらその開始時に次回分を登録し直す方式にしています。

1. 設定した時刻のうち、現在より後で最も近いものを選ぶ。
2. その時刻までの待ち時間を初期遅延にして、1回限りのジョブを登録する。
3. ジョブが動いたら、最初に次回分を登録してから取得を行う (取得に失敗しても予約が途切れない)。

端末の再起動後も WorkManager がジョブを保持します。アプリを起動したときにも予約を確認し、無ければ登録します。旧版の24時間ごとの定期ジョブは、起動時に自動で取り消します。

### API を使っていない理由

最初は `rewards.bing.com/api/getuserinfo` を呼ぶ方式で作りました。しかし、現在のダッシュボードでは、ダッシュボード自身が呼んでいるこの API も 401 を返しており、使えない状態でした。ポイントの数字はサーバー側で生成された画面に含まれているので、描画された画面から読む方式にしています。

## 取得ログの見方

ホーム画面の小さい文字が、直前の取得結果です。長押しでコピーできます。Cookie の値などは出さず、ホスト名やパス、見つかったポイントの取得方法だけを出します。

| 表示 | 意味 |
| --- | --- |
| `OK ○○ pt` | 取得に成功した |
| `NOT LOGGED IN` | セッションがない。「ログイン」からやり直す |
| `ERROR points not found on page` | 画面は開けたが、ポイント数が見つからなかった。末尾の `probe:` の行に、画面の数字とその直前の行が出る |
| `ERROR timeout` | 60秒以内に終わらなかった |
| `ERROR load error ...` | ページの読み込みに失敗した (通信など) |

`points not found on page` が出た場合は、Rewards の画面の文言やレイアウトが変わった可能性があります。`probe:` の行を見て、`RewardsClient.kt` の `SCRAPE` を直します。

## 注意点

- **非公式の方法です。** Rewards の公式 API はなく、画面から読み取っているため、Microsoft 側の変更で予告なく動かなくなることがあります。自分のアカウントのポイントを自分の端末で読むだけの用途ですが、利用規約の扱いは各自で確認してください。
- **バックグラウンド実行が止まることがあります。** WorkManager は端末の省電力機能の影響を受けます。OPPO / ColorOS など制限の強い端末では、アプリの自動起動を許可して、バッテリー最適化から除外してください。
- **実行時刻は正確ではありません。** 指定した時刻の数分後から、省電力状態では数十分以上遅れることがあります。電源オフや圏外で時刻を過ぎた場合は、復帰後に1回だけ取得されます。秒単位の正確さが必要なら、AlarmManager の正確なアラーム (権限が必要) への切り替えが必要です。
- **ログインの有効期間は不明です。** セッションが切れると通知が出るので、そのときにアプリを開いて再ログインします。
- **グラフは2回以上取得すると表示されます。** グラフの横軸は実際の時刻なので、1日に複数回取得した場合も間隔どおりに並びます。
- 取得のたびに1件ずつ記録が増えます (1日4回なら1年で約1,500件)。保存は軽いJSONなので、この程度なら問題ありません。「今すぐ取得」を押した分も記録されます。
- 累計ポイントは取得していません。
- 記録は端末内にだけ保存されます。外部には送信しません。

## 今後の変更の目安

- ポイント数の取得は `data/RewardsClient.kt` の `SCRAPE` に集まっています。画面の変更に追従するときは、基本的にここだけを直します。
- 保存方式を変えたい場合は、`PointStore` の公開関数 (`entries`、`upsert`、`status`、`setStatus`) を保ったまま中身を差し替えれば、ほかのファイルは変更不要です。
- 初期の取得時刻を変えたい場合は、`ScheduleStore.kt` の `DEFAULT` を編集します。
